# v0.11.2 synchronization verification

Date: 2026-08-03

Branch: `codex/sync-upstream-v0.11.2`

This record bounds the evidence for the fork synchronization. It is source and
isolated-runtime evidence, not production deployment evidence.

## Canonical gates

The final candidate passed:

- `npm run lint` in host context with `GOMAXPROCS=4` and `GOFLAGS=-p=4`;
- `go build ./...`, `go test -race ./...`, and `go vet ./...`;
- frontend `typecheck`, `typecheck:e2e`, and all 1,275 Vitest tests;
- `npm run sqlc` and `npm run api` with no generated-tree drift; and
- the tagged CLI e2e suite, including isolated daemon lifecycle probes.

The sandbox-visible lint result was not used because the private-key permission
test cannot observe authoritative host mode bits there. The same complete gate
passed in host context.

The Docker socket was available. `agent-ci run --all` correctly refused to
invent the Azure variables required by the release workflow. A narrowed local
run of `.github/workflows/go.yml` was started with two-job concurrency, but its
cold runner-image download remained incomplete and was stopped after bounded
waiting. The synchronization pull request's exact-head Go and Frontend checks
are therefore the workflow-level authority; this local runner attempt is not
counted as a pass.

## Isolated runtime canary

A candidate binary was built from the synchronization branch and run with a
disposable data directory, run file, loopback port `33081`, tmux directory, and
git repository. The production AO service, database, and tmux server were not
modified.

Observed results:

- the daemon reported `ready`, `health: ok`, and `ready: ready`;
- a disposable project registered successfully;
- a fake-agent worker spawned in a new worktree;
- kill, restore, and a second kill succeeded;
- the daemon stopped cleanly, restarted against the same database, and
  preserved the terminated session record; and
- the restarted daemon again reported ready before final clean shutdown.

## Evidence boundaries

Focused tests, rather than live external mutations, cover GitHub App token
selection and minimum-permission behavior, Linear read-only intake and worker
credential filtering, repeated PR ownership, bot review continuation, and
commented-thread refresh. This canary deliberately did not use production
credentials, claim a real pull request, mutate Linear, or expose the Dashboard.

The known `setsid` process-escape boundary remains open. The upstream v0.11.2
SID reaper does not provide cgroup-owned containment, and this synchronization
does not claim otherwise.
